## 2. 주요 보완 사항 (Critical Checkpoints)

### 2.1 위치 기반 서비스 (LBS) 고도화

**이슈:** - 핫플레이스(예: 강남역, 한강공원)에서 수백 명의 유저/친구 마커가 겹칠 경우 앱 성능 저하 및 UX 가독성 문제 발생.
- 초기 '장소(Place)' 데이터 부족으로 인한 체크인 기능 활용도 저하.

**보완 솔루션:**
1.  **마커 클러스터링 (Clustering) 도입**
    - **기술:** Naver Map SDK의 클러스터링 기능 또는 서버 사이드 클러스터링(Geohash 기반) 적용.
    - **UX:** 줌 레벨에 따라 겹친 마커를 `10+`, `50+` 형태의 원형 숫자로 표현하고, 클릭 시 펼쳐지도록 구현.
2.  **장소 데이터 확보 전략 (POI)**
    - **Phase 1:** 운영자가 주요 '펫 프렌들리' 장소(공원, 카페 등) 수동 등록.
    - **Phase 2:** Google Places API 또는 Naver 지역 검색 API 연동.
    - **Phase 3:** **"장소 제보하기"** 기능 추가 (유저가 직접 신규 장소 등록 요청 -> Admin 승인).

### 2.2 게이미피케이션 & 어뷰징 방지 (Anti-Abusing)

**이슈:**
- 차량/자전거 이동을 통한 산책 거리 조작.
- GPS 조작 앱을 이용한 원격 장소 체크인 및 뱃지 획득.

**보완 솔루션:**
1.  **산책 속도 제한 (Speed Limit Logic)**
    - 평균 시속 **15km/h 이상**이 1분 이상 지속될 경우, 해당 구간을 산책 거리에서 제외하거나 경고 메시지 노출.
    - `WalkRecord` 저장 시 `max_speed`, `avg_speed` 검증 로직 추가.
2.  **체크인 지오펜싱 (Geofencing)**
    - 장소 체크인 시, 해당 장소 좌표 반경 **50m~100m 이내**에 유저가 존재해야만 인증 버튼 활성화.

### 2.3 Gold 경제 시스템 & 법적 리스크 관리

**이슈:**
- 유료 결제 Gold와 이벤트 무료 지급 Gold가 혼재될 경우, 환불 처리 및 유효기간 적용 시 법적 문제 소지 있음.

**보완 솔루션:**
1.  **Gold 구분 관리 (DB Schema 변경)**
    - `users` 테이블 또는 `wallet` 테이블에서 Gold를 분리 관리.
    ```sql
    ALTER TABLE users ADD COLUMN paid_gold_balance INT DEFAULT 0; -- 환불 가능, 유효기간 김
    ALTER TABLE users ADD COLUMN free_gold_balance INT DEFAULT 0; -- 환불 불가, 유효기간 짧음
    ```
2.  **소진 우선순위 로직**
    - 사용자가 Gold 소모 시, **무료 Gold(free)를 우선 차감**하고 부족분만 유료 Gold(paid)에서 차감하는 로직 적용 (User-Friendly Policy).

### 2.4 콘텐츠 리스크 관리 (Trust & Safety)

**이슈:**
- 채팅/커뮤니티 내 성인물, 혐오 이미지 업로드 리스크.
- 악성 유저에 대한 즉각적인 제재 수단 부족.

**보완 솔루션:**
1.  **이미지 필터링 자동화**
    - AWS Rekognition 또는 Google Cloud Vision API를 활용하여 이미지 업로드 시 `NSFW(Not Safe For Work)` 스코어 체크.
    - 기준 점수 초과 시 업로드 자동 차단.
2.  **Circuit Breaker (자동 임시 제재)**
    - 단기간(예: 1시간) 내에 **신고가 5회 이상 누적**된 유저는 자동으로 글쓰기/채팅 권한을 **24시간 임시 정지** 시키는 백엔드 로직 구현.

### 2.5 AI 서비스 안정성 (Latency Handling)

**이슈:**
- 트래픽 폭주 시 AI 생성 서버 대기 시간 증가 및 타임아웃 발생.
- 생성 실패 시 Gold만 차감되는 트랜잭션 오류 가능성.

**보완 솔루션:**
1.  **비동기 처리 및 알림 (Async & Push)**
    - 클라이언트는 요청 후 `request_id`만 받고 대기하지 않음.
    - 작업 완료 시 **FCM(Firebase Cloud Messaging)**으로 "AI 프로필 생성이 완료되었습니다!" 알림 발송.
2.  **보상 트랜잭션 (Compensating Transaction)**
    - AI 생성 실패(Error) 발생 시, 차감된 Gold를 자동으로 원복하고 "죄송합니다" 알림과 함께 소정의 보상(무료 Gold) 지급 로직 고려.

## 3. 필수 추가 기능 정의 (Functional Additions)

### 3.1 Admin(관리자) 백오피스
> 앱 런칭과 동시에 운영팀이 사용할 수 있어야 함.

| 모듈 | 주요 기능 |
| :--- | :--- |
| **대시보드** | DAU, MAU, 신규 가입, 매출(Gold), AI 생성 건수 실시간 확인 |
| **회원 관리** | 회원 조회, 강제 탈퇴, 활동 정지(Ban), 비밀번호 초기화 |
| **신고 관리** | 접수된 신고 리스트, 신고 내용(채팅/게시글) 확인, 처리(승인/반려) |
| **Gold 관리** | CS 처리를 위한 Gold 수동 지급/차감 및 사유 기록 |
| **장소 관리** | 체크인 장소(Place) 데이터 추가/수정/삭제 |

### 3.2 프라이버시 매트릭스 (Ghost Mode)
> 위치 기반 서비스의 사생활 보호를 위한 설정 기능.

- **설정 메뉴:** `설정 > 개인정보 및 위치 > 내 위치 표시`
- **옵션:**
    - **전체 공개:** 모든 유저에게 지도상 내 위치 노출.
    - **친구만 공개:** 맞팔로우한 친구에게만 노출.
    - **유령 모드 (Ghost Mode):** 누구에게도 위치를 노출하지 않음 (단, 친구 찾기 기능 사용 제한될 수 있음).

### 3.3 회원 탈퇴 정책 (Data Retention)
- **정책:** 탈퇴 시 개인 식별 정보는 즉시 파기하나, 산책 경로 데이터(비식별화)는 통계 목적으로 유지할지 여부 결정 필요.
- **구현:** `soft delete` (DB flag 처리) 후 30일 뒤 배치(Batch)로 `hard delete` 하는 방식 권장 (실수 방지 및 CS 대응).

GoldPet 프로젝트는 **Flutter + Spring Boot + PostGIS**라는 강력한 기술 스택 위에 설계되었습니다. 본 보완 문서에서 지적된 **어뷰징 방지, 콘텐츠 리스크 관리, 경제 시스템의 유연성**만 개발 단계에서 선제적으로 반영된다면, 단순한 펫 앱을 넘어 **지속 가능한 플랫폼**으로 성장할 수 있을 것입니다.
